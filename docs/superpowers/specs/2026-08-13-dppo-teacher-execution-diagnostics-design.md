# DPPO 教师标签与快层执行诊断设计

## 目标

在扩大训练规模前，解释“预训练动作拟合改善，但在线奖励和快层修复率下降”的原因。本次只增加观测和离线诊断，不修改奖励函数、DPPO 更新、动作投影或 CLARABEL 求解模型。

## 诊断范围

### 在线训练耗时观测

在现有在线训练历史中增加四个只读字段：

- `fast_solver_run_count`：实际调用 CLARABEL 的慢步数；
- `fast_solver_mean_time_seconds`：实际调用时的平均求解耗时；
- `fast_solver_max_time_seconds`：单次最大求解耗时；
- `fast_solver_total_time_seconds`：累计求解耗时。

`not_run` 或没有快层结果的慢步不进入平均值分母，避免把零耗时混入 CLARABEL 性能统计。这些字段不参与奖励和梯度计算。

### 三类教师标签诊断

新增独立命令，读取 v2 专家数据集中的验证集和测试集，按 `cost`、`reliability`、`balanced` 三类教师分组。对每条保存的专家动作重放相同 Episode 和慢步状态，再通过当前投影器、CLARABEL 快层及奖励计算链执行。

每类教师统计：

- 样本数；
- 平均奖励；
- 原始动作可行率；
- 投影修改比例；
- 投影拒绝率；
- 快层修复成功率；
- CLARABEL 运行次数、平均/最大/累计求解耗时；
- 最终拒绝原因计数。

训练集不参与诊断，避免用模型已经学习过的样本产生偏乐观判断。

## 输出

- `teacher_transition_metrics.csv`：逐条记录，包含分区、教师、Episode seed、慢步和上述执行指标；
- `teacher_summary.json`：三类教师汇总和诊断结论。

诊断结论按明确规则给出：

1. 某类教师样本数少于 3，只报告样本不足，不据此调整比例；
2. 某类教师平均奖励和快层修复率都明显较差，则扩大训练前降低该类标签占比；
3. 教师标签整体原始可行率高但快层修复率低，则优先修正标签生成中的节点或保留时间选择；
4. 三类教师表现接近且求解耗时不是瓶颈，才直接扩大 Episode 数量。

## 错误处理

- 数据集配置哈希、状态维度或动作维度不匹配时立即拒绝；
- 只允许验证集与测试集；
- Episode 重放状态必须与保存状态一致；
- 所有汇总数值必须有限；
- 某类教师不存在时写出样本数 0，不伪造评价。

## 核心测试

只覆盖本次新增行为：

1. 在线 rollout 正确累计 CLARABEL 运行次数及平均/最大/累计耗时；
2. `not_run` 不进入耗时平均值；
3. 教师诊断严格排除训练集并正确按三类教师分组；
4. 逐条 CSV 和汇总 JSON 字段完整；
5. 状态重放不一致时拒绝诊断。

完成核心测试后，直接在 `gpu_exact_200_v2` 数据集上运行诊断，并据结果给出扩大训练前唯一需要的修复动作。
