# DPPO 主算法替换设计规格

日期：2026-08-10  
状态：已完成对话设计，等待书面规格 review  
目标分支：`codex/dppo-main-algorithm`

## 1. 研究目标

本设计把 Diffusion Policy Policy Optimization（DPPO）作为活动分支中
唯一的慢时间尺度学习算法。此前值函数算法的实现、配置、测试、文档和
结果从本分支移除，仅在独立归档分支和 Git 历史中保留，待主算法完成后
再按单独规格引入对比基线。

论文主方法暂用名称“约束投影 DPPO”。它在每个慢时间尺度决策点一次性
生成整条 SFC 的联合部署意图，再由确定性投影器和共享快层执行器完成
资源、故障域、可靠性、路由和 SLA 约束处理。

设计目标如下：

1. 使用论文 DPPO 的连续高斯扩散、两层 MDP、状态价值函数、GAE 和
   PPO 裁剪更新，不把普通离散 PPO 错称为 DPPO。
2. 每次联合决策配置声明的全部 VNF，而不是逐个 VNF 与环境交互。
3. 每个 VNF 独立选择 2 或 3 副本。
4. 配置声明的全部 MEC 和 1 个中心云共同参与部署评分，不再使用独立云开关。
5. 用连续主副本、备用副本保留时间替代三档离散保留策略。
6. 第一阶段仅使用仿真数据生成专家示范，不依赖外部数据集。
7. 保留双时间尺度快层审计、精确修复和成本计算闭环。
8. 分开报告原始动作、投影动作和最终执行动作，避免快层修复掩盖
   DPPO 自身的动作质量。

## 2. 范围和非目标

### 2.1 本阶段范围

- 默认论文调试配置为 3 个 VNF、5 个 MEC 和 1 个中心云，但实现不得
  写死这些数量。
- 状态和动作维度从配置中的 MEC、中心云和 VNF 定义自动计算；默认配置
  分别得到 78 维状态和 27 维动作。
- 历史动作相关特征改为 DPPO 语义并升级状态版本。
- 先生成仿真专家数据并进行扩散行为克隆，再进行 DPPO 在线微调。
- CPU 用于单元测试和小规模烟雾实验；正式训练支持显式选择 CUDA。
- 本阶段只实现和验证 DPPO 主算法，不同时维护其他学习算法基线。

### 2.2 本阶段非目标

- 不在首个 DPPO 闭环中接入公开真实数据集。
- 不让扩散策略提前生成未来多个慢窗口的开环动作序列。
- 不在第一版加入新的多权重奖励函数。
- 旧学习算法的受版本控制模型引用和历史结果从活动分支删除，但归档分支
  继续提供可恢复副本。
- 不声称仿真教师策略是全局最优解。
- 不在第一版使用 UNet、Transformer 或图神经网络扩散头。
- 不要求同一个已训练 MLP 检查点直接跨不同节点数或 VNF 数使用；不同
  规模允许重新生成专家数据并重新训练，但不得修改核心代码。

## 3. 总体架构

系统分为六层：

1. **因果状态层**：按场景规模构建状态，预测器只能读取已经执行的请求。
2. **扩散策略层**：条件 MLP 从高斯噪声逐步生成配置驱动的连续动作。
3. **动作解码层**：把连续动作转换为每个 VNF 的副本数、节点排名和
   主备保留时间。
4. **可行性投影层**：处理故障节点、重复节点、故障域和基础资源约束。
5. **快层执行层**：共享执行器进行精确审计、优化修复和 SFC 执行。
6. **DPPO 更新层**：根据环境奖励、价值估计和每步去噪似然更新策略。

数据流固定为：

```text
仿真状态
  -> DPPO 连续动作
  -> 结构解码
  -> 可行性投影
  -> 快层审计/修复/执行
  -> 成本与违约奖励
  -> GAE 和 PPO 更新
```

专家预训练流固定为：

```text
仿真状态采样
  -> 三类教师策略
  -> 约束审计过滤
  -> 专家示范数据集
  -> 条件扩散行为克隆
  -> DPPO 在线微调初始模型
```

## 4. 配置驱动的 DPPO 状态（默认 78 维）

移动性、工作负载、节点、VNF 和 SFC 静态特征继续复用现有编码公式。
其中请求预测必须只使用已经执行完成的请求前缀，节点空闲资源必须来自
上一快时隙的最终审计。

当前默认状态最后 11 维含有旧离散控制器的三档保留策略和云开关，不能原样
用于 DPPO。DPPO 版本将它们替换为：

1. 上一动作的平均归一化副本数；
2. 上一动作中使用 3 副本的 VNF 比例；
3. 上一动作的平均归一化主副本保留时间；
4. 上一动作的平均归一化备用副本保留时间；
5. 上一原始动作被投影器修改的分量比例；
6. 当前热副本比例；
7. 当前中心云副本比例；
8. 上一窗口请求成功率；
9. 上一窗口 SLA 违约率；
10. 上一窗口归一化总成本；
11. 上一窗口快层修复失败率。

设 MEC 数量为 `M`、VNF 数量为 `F`，并固定包含 1 个中心云。现有平铺
编码的状态维度自动计算为：

```text
state_dim = 8 * M + 4 * F + 26
```

默认 `M=5`、`F=3` 时得到 78 维；例如 `M=8`、`F=3` 时自动得到
102 维。代码不得把 `78` 用作构造器合法性的硬编码条件。

状态模式版本升级为 `dppo-v1-flat`。维度相同不代表
语义相同，检查点加载必须同时校验模式版本、实际状态维度、MEC 数量、
计算节点数量和 VNF 数量。

状态编码拆成共享的基础特征编码和 `DPPOHistoryEncoder`。活动分支不保留
旧动作历史编码器；模式不匹配的任何检查点都必须拒绝加载。

## 5. 配置驱动的连续动作（默认 27 维）

设 VNF 数量为 `F`，可选计算节点数量为 `N`。动作维度定义为：

```text
action_dim = F * N + F + 2 * F = F * N + 3 * F
```

默认 `F=3`、`N=6`，因此动作维度为 27。扩散模型内部与数据集统一把
动作归一化到 `[-1, 1]`。

例如把 MEC 从 5 个扩充到 8 个时，`N=9`，动作维度自动变为 36。
动作解析必须使用配置生成的函数 ID 和节点 ID 顺序，禁止依赖固定切片
`0:18`、`18:21` 或其他默认场景常数。

最终去噪样本在进入解码器前逐分量截断到 `[-1, 1]`。Rollout Buffer
同时保存未截断的完整去噪样本和用于环境执行的截断动作；PPO 概率比使用
未截断高斯去噪样本的对数概率，不能根据投影或截断后的动作重新伪造概率。

### 5.1 节点评分矩阵：18 维

`node_scores[f, n]` 表示 VNF `f` 对节点 `n` 的部署偏好。节点集合按
拓扑提供的稳定 ID 顺序包含全部 MEC 和 1 个中心云。中心云与 MEC 使用同一评分
机制，不再设置 `cloud_allowed` 开关。

### 5.2 冗余评分：3 维

`replica_scores[f]` 决定 VNF `f` 的副本数：

- 分数小于 0：2 副本；
- 分数大于或等于 0：3 副本。

阈值必须固定并写入检查点元数据，训练和评估不得使用不同阈值。

### 5.3 连续保留时间：6 维

每个 VNF 输出一个主副本和一个备用副本保留值。归一化值 `x` 按下式
转换为秒：

```text
retention_seconds = (x + 1) / 2 * maximum_retention_seconds
```

同一 VNF 的所有备用副本共享备用保留时间。执行器再按快时隙长度向上
取整为保留时隙数，保证正的保留时间至少覆盖一个快时隙。

## 6. 动作解码与可行性投影

### 6.1 原始解码

每个 VNF 按以下固定顺序解码：

1. 根据冗余评分得到 2 或 3 副本；
2. 对当前仍可运行的节点按部署评分降序排序；
3. 最高分节点作为主副本；
4. 后续节点作为备用副本；
5. 分数完全相同时以节点 ID 升序打破平局；
6. 主副本使用主保留时间，所有备用副本使用备用保留时间。

### 6.2 投影规则

投影器按以下顺序处理：

1. 删除故障或不属于拓扑的节点；
2. 禁止同一 VNF 的多个副本位于同一节点；
3. 优先选择不同故障域的节点；
4. 检查基础内存和 CPU 必要条件；
5. 必要时按原始评分顺序替换节点；
6. 如果仍无法满足必要条件，输出明确的投影失败结果，不伪造部署。

投影器只做确定性必要条件修正，不复制快层精确优化逻辑。路由、完整
资源占用、端到端时延和精确可靠性仍由共享快层审计与优化器负责。

### 6.3 可观测统计

每个慢窗口必须记录：

- 原始动作是否直接可行；
- 投影修改的动作分量数和比例；
- 投影是否成功；
- 快层修复尝试、成功和失败次数；
- 最终约束拒绝次数。

PPO 回放的是扩散策略实际采样的原始连续动作和完整去噪链，不能把投影后
动作冒充为策略采样动作。

## 7. DPPO 慢层意图接口

DPPO 通过算法内部与执行器解耦的 `SFCDeploymentIntent` 提交部署：

```text
SFCDeploymentIntent
  decision_slot
  valid_until_slot
  function_intents[function_id]
    replica_count
    preferred_node_ids
    primary_retention_seconds
    backup_retention_seconds
  source_algorithm
```

共享慢层执行核心只接收该接口，不识别 DPPO 神经网络内部结构。

- `DPPOIntentAdapter`：把投影后的连续动作转换为通用意图。

现有环境拆分为：

- `SlowTimescaleExecutionCore`：管理因果轨迹、状态推进、快层执行、指标和奖励；
- `DPPOSlowTimescaleEnvironment`：接收当前规模对应的连续动作并保存投影信息；
- `DPPOSlowTimescaleEnvironment`：作为活动分支唯一的学习环境入口。

禁止在同一个 `step()` 中保留旧离散动作的兼容分支。

## 8. 连续保留时间执行语义

新增状态化保留跟踪器。它以 `(function_id, node_id)` 为键记录实例到期
时隙：

1. 慢层新意图刷新被选主、备用副本的到期时隙；
2. 请求命中实例时按既有运行语义刷新活动状态；
3. 到期后实例变冷，不再占用热实例内存；
4. 故障节点上的实例立即不可用；
5. 快层修复生成的新节点按其主备身份使用相应保留时间；
6. Episode 重置时清空跟踪器。

保留时间必须真实影响冷启动次数、活动内存和运行成本，不能只作为报告字段。

## 9. 仿真教师策略与专家数据

### 9.1 教师定义

第一版提供三种确定性教师：

- **成本优先教师**：在满足硬约束的前提下偏向近端 MEC、2 副本和短保留；
- **可靠性优先教师**：偏向不同故障域、3 副本、中心云备份和长保留；
- **平衡教师**：先满足可靠性及 SLA，再在可行候选中选择总成本较低者。

教师不是最终主算法，也不要求全局最优。教师候选必须经过同一个投影器、
约束审计器和快层执行器评估，只有成功执行或带明确拒绝原因的样本才能落盘。

教师作出决策时只能读取与 DPPO 相同的当前状态、公开配置和历史
统计，禁止读取当前慢窗口尚未发生的真实请求或故障。教师不能先试完多个
候选在同一条未来轨迹上的结果，再用事后最低成本候选作为标签。候选执行
后的真实结果只用于样本质量记录和最终可行性过滤。

教师把节点完整排名编码为唯一连续标签。对 `N` 个节点，排名为 `j`
（从 0 开始）的节点分数固定为：

```text
teacher_node_score(j) = 1 - 2 * j / (N - 1)
```

2 副本标签的冗余分数固定为 `-1`，3 副本固定为 `+1`；保留时间使用
动作缩放公式的逆变换编码。这样相同教师、状态和种子必定产生相同的
配置驱动标签，不依赖任意浮点打分。

场景构建时必须验证可运行计算节点的配置数量至少为 3，保证 3 副本动作
和排名公式有定义。错误配置应在训练开始前失败，而不是运行中降级。

### 9.2 场景覆盖

数据生成至少覆盖：

- 不同列车位置、驻留时间和切换边界；
- 低、中、高和突发请求负载；
- 无故障、单节点故障、多节点及多故障域故障；
- 中心云正常与故障；
- 低风险和预测高风险窗口；
- 资源充足与资源紧张状态。

### 9.3 数据模式

每条样本保存：

```text
state[state_dim]
expert_action[action_dim]
teacher_name
episode_seed
decision_slot
raw_feasible
projection_change_ratio
final_feasible
run_cost
route_cost
cold_start_cost
exact_sfc_reliability
sla_violations
```

只有 `final_feasible=true` 的样本进入扩散行为克隆训练集。被拒绝样本单独
保存在诊断分区，用于分析教师和投影失败原因，不作为专家动作监督标签。

`raw_feasible` 表示未经节点替换的原始解码部署可以直接通过必要条件和
精确审计；任何节点替换、副本数变更或动作截断都必须单独记录，不能仍把
该样本统计为原始可行。

训练、验证、测试集必须按 Episode 种子分组切分，禁止同一 Episode 的相邻
状态出现在不同数据分区。数据文件同时保存状态、动作模式版本和配置哈希。

## 10. 扩散行为克隆预训练

第一版使用条件 MLP 噪声预测网络。输入为带噪动作 `a_k`、去噪步 `k` 和
当前配置对应的状态，输出与动作同形的预测噪声。

固定初始设置：

- DDPM 去噪步数 `K=20`；
- 动作范围 `[-1, 1]`；
- 余弦噪声调度；
- 训练目标为真实噪声与预测噪声的均方误差；
- 训练和验证使用不同 Episode 种子；
- 保存动作归一化、噪声调度和模式版本。

预训练同时报告：

- 训练和验证去噪损失；
- 解码后的 2/3 副本分布；
- 原始动作可行率；
- 投影修改率；
- 与教师动作的部署重合率和保留时间误差；
- 执行后的成本、可靠性和 SLA 指标。

不能只凭噪声损失判断预训练成功。

## 11. DPPO 在线微调

DPPO 把每个环境动作内部的去噪过程视为内层 MDP，把慢窗口推进视为外层
环境 MDP。

### 11.1 策略与价值函数

- 策略保存完整去噪链 `a_K, ..., a_0` 和每一步旧对数概率；
- 每一步反向扩散使用可解析的高斯条件概率；
- 价值网络只输入当前配置对应的环境状态，不输入中间带噪动作；
- 第一版只微调最后 `K'=5` 个去噪步骤，前 15 步使用冻结的预训练参数；
- 评估使用确定性或固定种子的去噪采样，正式结果记录采样设置。

### 11.2 优势与更新

- 外层慢窗口使用环境折扣和 GAE；
- 同一环境动作的内层去噪步骤共享外层优势；
- 使用去噪折扣降低高噪声早期步骤的梯度权重；
- 使用 PPO 裁剪概率比更新可训练的去噪步骤；
- 使用价值损失、梯度裁剪和有限数检查；
- Rollout Buffer 只保存当前策略采集的轨迹，更新后清空，不使用离策略
  经验回放池。

### 11.3 无可行部署

当投影器无法构造最低必要条件的部署时：

- 环境记录硬违约并推进窗口；
- 该原始扩散动作仍属于当前策略轨迹，保留其对数概率和负奖励；
- 不伪造投影后动作；
- 快层执行器不执行不存在的部署。

## 12. 奖励与指标

第一版继续使用已批准的简化奖励：

```text
total_cost = run_cost + route_cost + cold_start_cost
reward = -(min(total_cost / maximum_window_cost, 1) + violation_penalty)
```

任何资源、可靠性、路由或 SLA 硬约束失败都令
`violation_penalty = 1`，否则为 0。第一版不新增需要调参的投影惩罚权重。

投影修改率、修复次数和原始可行率只作为训练诊断与实验指标。在后续消融
实验中，只有明确证据表明策略依赖投影器且无法改善时，才单独设计固定
投影成本，并作为新设计再次 review。

## 13. 配置驱动扩展、检查点和输出隔离

### 13.1 单一规模描述对象

新增不可变的 `ScenarioDimensions`，由配置和已构建拓扑一次性生成：

```text
mec_node_ids
cloud_node_id
compute_node_ids
function_ids
mec_count
compute_node_count
function_count
state_dim
action_dim
```

状态编码器、动作空间、扩散网络、数据集、环境、检查点和评估器都接收同一个
对象，禁止各模块重复推导或分别写常数。节点和函数顺序也由该对象统一提供。

### 13.2 必须配置化的参数

以下信息必须从 `configs/debug.yaml` 或同模式实验配置读取：

- `topology.mec_count` 和 `topology.include_cloud`；
- 各 MEC 与中心云的容量、可靠性、故障域和网络参数；
- `rl_scenario.functions` 中每个 VNF 的 ID、内存、CPU、镜像、执行时间、
  冷启动时间和输出比例；
- `rl_scenario.sfc` 的函数顺序、截止时间、可靠性目标、优先级和输入规模；
- `dppo.action.maximum_retention_seconds` 与 `replica_threshold`；
- `dppo.diffusion.steps`、`fine_tuned_steps`、噪声调度和隐藏层；
- `dppo.dataset` 的 Episode 数、种子范围、数据切分和输出目录；
- `dppo.training` 的 PPO、GAE、批量、优化器、设备和检查点参数。

`build_rl_functions()` 和 `build_rl_sfc()` 不再在 Python 中写死三个函数的
业务参数，而是负责校验和构造配置中声明的实体。

扩充实验的标准流程是：复制配置、修改规模与实体参数、重新生成专家数据、
重新训练对应检查点。核心源代码不应因 3、5、8 或其他合法 MEC 数量而改变。

第一版平铺 MLP 检查点只能用于它训练时的规模。加载不同规模时必须给出
明确的维度不匹配错误。未来若要求同一模型跨规模直接推理，可以在保持
`ScenarioDimensions`、环境和投影接口不变的前提下，用带节点掩码的
Transformer 或 GNN 替换平铺编码器和 MLP 扩散骨干；该能力不属于首版范围。

## 15. 测试策略

实现严格遵循测试先行。测试分为：

1. **动作单元测试**：动态维度、范围、2/3 阈值、节点排名、TTL 缩放；
2. **投影单元测试**：故障节点、重复节点、故障域、资源不足和确定性平局；
3. **保留时间测试**：到期、刷新、故障、冷启动和内存占用；
4. **数据测试**：固定种子复现、分区无泄漏、模式版本校验；
5. **扩散测试**：前向加噪、反向形状、对数概率和损失均为有限数；
6. **DPPO 测试**：GAE、裁剪概率比、冻结早期去噪步、Rollout 清空；
7. **环境集成测试**：一次联合部署全部 VNF、快层调用次数、奖励闭环；
8. **检查点测试**：保存重载一致和任何不匹配模式检查点拒绝；
9. **烟雾测试**：小数据预训练、一 Episode 在线更新和临时目录评估。

维度和动作测试至少参数化覆盖 `(M=3,F=2)`、`(M=5,F=3)` 和
`(M=8,F=3)`；默认场景运行完整集成测试，其他规模运行构造、编码、解码、
投影和模型前向测试。测试必须证明改变配置后无需修改源代码。

除明确退役并删除的旧算法测试外，所有公共基础设施测试必须继续通过。

## 16. 实验设计

主算法完成阶段至少评估：

- 成本优先、可靠性优先和平衡规则教师；
- 仅扩散行为克隆；
- 完整约束投影 DPPO；
- 去掉快层修复的 DPPO；
- 固定 2 副本与每 VNF 独立 2/3 副本的 DPPO。

其他强化学习基线在 DPPO 主算法通过完整验证后另立规格接入，不属于本阶段
代码和测试范围。

统一报告：

- 请求成功率和 SLA 违约率；
- 平均、峰值、P95、P99 端到端时延；
- 最小和平均精确 SFC 可靠性；
- 冷启动次数及活动内存；
- 中心云执行率；
- 每 VNF 的 2/3 副本分布；
- 主、备用平均保留时间；
- 原始可行率、投影修改率和最终拒绝率；
- 快层修复尝试、成功和失败次数；
- 运行、路由、冷启动和总成本；
- 训练时间、采样量和推理时间。

所有随机方法使用相同 Episode 种子集合并报告多随机种子均值、标准差和
置信区间。

## 17. 完成标准

代码实现完成必须同时满足：

1. 状态版本为 `dppo-v1-flat`，维度由配置计算且无未来请求泄漏；
2. DPPO 生成与配置规模匹配的有限连续动作；
3. 一次动作联合包含配置定义的全部 VNF；
4. 每个 VNF 可独立选择 2 或 3 副本；
5. 中心云通过同一节点评分参与选择；
6. 连续保留时间真实改变冷启动和活动内存；
7. 仿真专家数据按 Episode 隔离切分；
8. 扩散预训练能够保存、加载并完成验证采样；
9. DPPO 能完成至少一次有限损失的在线更新；
10. 原始、投影和最终动作指标可分别导出；
11. 活动源码、测试、配置和运行脚本不再导入或调用退役算法接口；
12. 完整测试、语法检查、临时预训练和在线烟雾训练全部通过；
13. 正式结果路径在用户另行批准前不被覆盖。
