# DPPO 主算法替换设计规格

日期：2026-08-10  
状态：已完成对话设计，等待书面规格 review  
目标分支：`codex/dppo-main-algorithm`

## 1. 研究目标

本设计把慢时间尺度主算法从 Double DQN（DDQN）替换为 Diffusion
Policy Policy Optimization（DPPO）。DDQN 代码和已训练模型暂时保留，
但只作为实验对比基线，不再代表论文提出的主算法。

论文主方法暂用名称“约束投影 DPPO”。它在每个慢时间尺度决策点一次性
生成整条 SFC 的联合部署意图，再由确定性投影器和共享快层执行器完成
资源、故障域、可靠性、路由和 SLA 约束处理。

设计目标如下：

1. 使用论文 DPPO 的连续高斯扩散、两层 MDP、状态价值函数、GAE 和
   PPO 裁剪更新，不把普通离散 PPO 错称为 DPPO。
2. 每次联合决策 3 个 VNF，而不是逐个 VNF 与环境交互。
3. 每个 VNF 独立选择 2 或 3 副本。
4. 5 个 MEC 和 1 个中心云共同参与部署评分，不再使用独立云开关。
5. 用连续主副本、备用副本保留时间替代三档离散保留策略。
6. 第一阶段仅使用仿真数据生成专家示范，不依赖外部数据集。
7. 保留双时间尺度快层审计、精确修复和成本计算闭环。
8. 分开报告原始动作、投影动作和最终执行动作，避免快层修复掩盖
   DPPO 自身的动作质量。

## 2. 范围和非目标

### 2.1 本阶段范围

- 固定论文调试场景为 3 个 VNF、5 个 MEC 和 1 个中心云。
- 状态仍为 78 维，但历史动作相关特征改为 DPPO 语义并升级状态版本。
- 主动作是 27 维连续向量。
- 先生成仿真专家数据并进行扩散行为克隆，再进行 DPPO 在线微调。
- CPU 用于单元测试和小规模烟雾实验；正式训练支持显式选择 CUDA。
- DDQN 与普通 PPO 保留为公平对比算法。

### 2.2 本阶段非目标

- 不在首个 DPPO 闭环中接入公开真实数据集。
- 不让扩散策略提前生成未来多个慢窗口的开环动作序列。
- 不在第一版加入新的多权重奖励函数。
- 不覆盖正式 DDQN 模型和历史论文结果文件。
- 不声称仿真教师策略是全局最优解。
- 不在第一版使用 UNet、Transformer 或图神经网络扩散头。

## 3. 总体架构

系统分为六层：

1. **因果状态层**：构建当前 78 维状态，预测器只能读取已经执行的请求。
2. **扩散策略层**：条件 MLP 从高斯噪声逐步生成 27 维连续动作。
3. **动作解码层**：把连续动作转换为每个 VNF 的副本数、节点排名和
   主备保留时间。
4. **可行性投影层**：处理故障节点、重复节点、故障域和基础资源约束。
5. **快层执行层**：共享执行器进行精确审计、优化修复和 SFC 执行。
6. **DPPO 更新层**：根据环境奖励、价值估计和每步去噪似然更新策略。

数据流固定为：

```text
仿真状态
  -> DPPO 连续动作
  -> 结构解码
  -> 可行性投影
  -> 快层审计/修复/执行
  -> 成本与违约奖励
  -> GAE 和 PPO 更新
```

专家预训练流固定为：

```text
仿真状态采样
  -> 三类教师策略
  -> 约束审计过滤
  -> 专家示范数据集
  -> 条件扩散行为克隆
  -> DPPO 在线微调初始模型
```

## 4. 78 维 DPPO 状态

移动性、工作负载、节点、VNF 和 SFC 静态特征继续复用现有编码公式。
其中请求预测必须只使用已经执行完成的请求前缀，节点空闲资源必须来自
上一快时隙的最终审计。

当前状态最后 11 维含有 DDQN 专属的三档保留策略和云开关，不能原样
用于 DPPO。DPPO 版本将它们替换为：

1. 上一动作的平均归一化副本数；
2. 上一动作中使用 3 副本的 VNF 比例；
3. 上一动作的平均归一化主副本保留时间；
4. 上一动作的平均归一化备用副本保留时间；
5. 上一原始动作被投影器修改的分量比例；
6. 当前热副本比例；
7. 当前中心云副本比例；
8. 上一窗口请求成功率；
9. 上一窗口 SLA 违约率；
10. 上一窗口归一化总成本；
11. 上一窗口快层修复失败率。

状态总维度保持 78，状态模式版本从 `ddqn-v2-78` 升级为
`dppo-v1-78`。维度相同不代表语义相同，检查点加载必须严格校验版本。

为了保留公平基线，状态编码拆成共享的前 67 维基础编码和两个版本化的
11 维历史编码：

- `DDQNHistoryEncoder` 保留 `ddqn-v2-78` 的旧动作语义；
- `DPPOHistoryEncoder` 实现上述 `dppo-v1-78` 新语义。

DDQN 基线不得读取 DPPO 历史特征，DPPO 也不得加载 DDQN 状态检查点。

## 5. 27 维连续动作

设 VNF 数量为 `F`，可选计算节点数量为 `N`。动作维度定义为：

```text
action_dim = F * N + F + 2 * F = F * N + 3 * F
```

当前 `F=3`、`N=6`，因此动作维度为 27。扩散模型内部与数据集统一把
动作归一化到 `[-1, 1]`。

最终去噪样本在进入解码器前逐分量截断到 `[-1, 1]`。Rollout Buffer
同时保存未截断的完整去噪样本和用于环境执行的截断动作；PPO 概率比使用
未截断高斯去噪样本的对数概率，不能根据投影或截断后的动作重新伪造概率。

### 5.1 节点评分矩阵：18 维

`node_scores[f, n]` 表示 VNF `f` 对节点 `n` 的部署偏好。节点集合按
固定 ID 顺序包含 5 个 MEC 和 1 个中心云。中心云与 MEC 使用同一评分
机制，不再设置 `cloud_allowed` 开关。

### 5.2 冗余评分：3 维

`replica_scores[f]` 决定 VNF `f` 的副本数：

- 分数小于 0：2 副本；
- 分数大于或等于 0：3 副本。

阈值必须固定并写入检查点元数据，训练和评估不得使用不同阈值。

### 5.3 连续保留时间：6 维

每个 VNF 输出一个主副本和一个备用副本保留值。归一化值 `x` 按下式
转换为秒：

```text
retention_seconds = (x + 1) / 2 * maximum_retention_seconds
```

同一 VNF 的所有备用副本共享备用保留时间。执行器再按快时隙长度向上
取整为保留时隙数，保证正的保留时间至少覆盖一个快时隙。

## 6. 动作解码与可行性投影

### 6.1 原始解码

每个 VNF 按以下固定顺序解码：

1. 根据冗余评分得到 2 或 3 副本；
2. 对当前仍可运行的节点按部署评分降序排序；
3. 最高分节点作为主副本；
4. 后续节点作为备用副本；
5. 分数完全相同时以节点 ID 升序打破平局；
6. 主副本使用主保留时间，所有备用副本使用备用保留时间。

### 6.2 投影规则

投影器按以下顺序处理：

1. 删除故障或不属于拓扑的节点；
2. 禁止同一 VNF 的多个副本位于同一节点；
3. 优先选择不同故障域的节点；
4. 检查基础内存和 CPU 必要条件；
5. 必要时按原始评分顺序替换节点；
6. 如果仍无法满足必要条件，输出明确的投影失败结果，不伪造部署。

投影器只做确定性必要条件修正，不复制快层精确优化逻辑。路由、完整
资源占用、端到端时延和精确可靠性仍由共享快层审计与优化器负责。

### 6.3 可观测统计

每个慢窗口必须记录：

- 原始动作是否直接可行；
- 投影修改的动作分量数和比例；
- 投影是否成功；
- 快层修复尝试、成功和失败次数；
- 最终约束拒绝次数。

PPO 回放的是扩散策略实际采样的原始连续动作和完整去噪链，不能把投影后
动作冒充为策略采样动作。

## 7. 通用慢层意图接口

为同时支持 DPPO 主算法和 DDQN 基线，引入与算法无关的
`SFCDeploymentIntent`：

```text
SFCDeploymentIntent
  decision_slot
  valid_until_slot
  function_intents[function_id]
    replica_count
    preferred_node_ids
    primary_retention_seconds
    backup_retention_seconds
  source_algorithm
```

共享慢层执行核心只接收该接口，不识别 DDQN 动作编号或 DPPO 神经网络。

- `DPPOIntentAdapter`：把投影后的连续动作转换为通用意图。
- `DDQNIntentAdapter`：把现有 12 动作和副本规划器结果转换为相同意图，
  仅用于基线评估。

现有环境拆分为：

- `SlowTimescaleExecutionCore`：管理因果轨迹、状态推进、快层执行、指标和奖励；
- `DPPOSlowTimescaleEnvironment`：接收 27 维连续动作并保存投影信息；
- `SlowTimescaleRLEnvironment`：保留现有 DDQN 离散包装器作为基线。

禁止在同一个 `step()` 中根据 Python 类型偷偷切换两套动作语义。

## 8. 连续保留时间执行语义

新增状态化保留跟踪器。它以 `(function_id, node_id)` 为键记录实例到期
时隙：

1. 慢层新意图刷新被选主、备用副本的到期时隙；
2. 请求命中实例时按既有运行语义刷新活动状态；
3. 到期后实例变冷，不再占用热实例内存；
4. 故障节点上的实例立即不可用；
5. 快层修复生成的新节点按其主备身份使用相应保留时间；
6. Episode 重置时清空跟踪器。

保留时间必须真实影响冷启动次数、活动内存和运行成本，不能只作为报告字段。

## 9. 仿真教师策略与专家数据

### 9.1 教师定义

第一版提供三种确定性教师：

- **成本优先教师**：在满足硬约束的前提下偏向近端 MEC、2 副本和短保留；
- **可靠性优先教师**：偏向不同故障域、3 副本、中心云备份和长保留；
- **平衡教师**：先满足可靠性及 SLA，再在可行候选中选择总成本较低者。

教师不是最终主算法，也不要求全局最优。教师候选必须经过同一个投影器、
约束审计器和快层执行器评估，只有成功执行或带明确拒绝原因的样本才能落盘。

教师作出决策时只能读取与 DPPO 相同的当前 78 维状态、公开配置和历史
统计，禁止读取当前慢窗口尚未发生的真实请求或故障。教师不能先试完多个
候选在同一条未来轨迹上的结果，再用事后最低成本候选作为标签。候选执行
后的真实结果只用于样本质量记录和最终可行性过滤。

教师把节点完整排名编码为唯一连续标签。对 `N` 个节点，排名为 `j`
（从 0 开始）的节点分数固定为：

```text
teacher_node_score(j) = 1 - 2 * j / (N - 1)
```

2 副本标签的冗余分数固定为 `-1`，3 副本固定为 `+1`；保留时间使用
动作缩放公式的逆变换编码。这样相同教师、状态和种子必定产生相同的
27 维标签，不依赖任意浮点打分。

### 9.2 场景覆盖

数据生成至少覆盖：

- 不同列车位置、驻留时间和切换边界；
- 低、中、高和突发请求负载；
- 无故障、单节点故障、多节点及多故障域故障；
- 中心云正常与故障；
- 低风险和预测高风险窗口；
- 资源充足与资源紧张状态。

### 9.3 数据模式

每条样本保存：

```text
state[78]
expert_action[27]
teacher_name
episode_seed
decision_slot
raw_feasible
projection_change_ratio
final_feasible
run_cost
route_cost
cold_start_cost
exact_sfc_reliability
sla_violations
```

只有 `final_feasible=true` 的样本进入扩散行为克隆训练集。被拒绝样本单独
保存在诊断分区，用于分析教师和投影失败原因，不作为专家动作监督标签。

`raw_feasible` 表示未经节点替换的原始解码部署可以直接通过必要条件和
精确审计；任何节点替换、副本数变更或动作截断都必须单独记录，不能仍把
该样本统计为原始可行。

训练、验证、测试集必须按 Episode 种子分组切分，禁止同一 Episode 的相邻
状态出现在不同数据分区。数据文件同时保存状态、动作模式版本和配置哈希。

## 10. 扩散行为克隆预训练

第一版使用条件 MLP 噪声预测网络。输入为带噪动作 `a_k`、去噪步 `k` 和
78 维状态，输出与动作同形的预测噪声。

固定初始设置：

- DDPM 去噪步数 `K=20`；
- 动作范围 `[-1, 1]`；
- 余弦噪声调度；
- 训练目标为真实噪声与预测噪声的均方误差；
- 训练和验证使用不同 Episode 种子；
- 保存动作归一化、噪声调度和模式版本。

预训练同时报告：

- 训练和验证去噪损失；
- 解码后的 2/3 副本分布；
- 原始动作可行率；
- 投影修改率；
- 与教师动作的部署重合率和保留时间误差；
- 执行后的成本、可靠性和 SLA 指标。

不能只凭噪声损失判断预训练成功。

## 11. DPPO 在线微调

DPPO 把每个环境动作内部的去噪过程视为内层 MDP，把慢窗口推进视为外层
环境 MDP。

### 11.1 策略与价值函数

- 策略保存完整去噪链 `a_K, ..., a_0` 和每一步旧对数概率；
- 每一步反向扩散使用可解析的高斯条件概率；
- 价值网络只输入 78 维环境状态，不输入中间带噪动作；
- 第一版只微调最后 `K'=5` 个去噪步骤，前 15 步使用冻结的预训练参数；
- 评估使用确定性或固定种子的去噪采样，正式结果记录采样设置。

### 11.2 优势与更新

- 外层慢窗口使用环境折扣和 GAE；
- 同一环境动作的内层去噪步骤共享外层优势；
- 使用去噪折扣降低高噪声早期步骤的梯度权重；
- 使用 PPO 裁剪概率比更新可训练的去噪步骤；
- 使用价值损失、梯度裁剪和有限数检查；
- Rollout Buffer 只保存当前策略采集的轨迹，更新后清空，不使用 DDQN
  经验回放池。

### 11.3 无可行部署

当投影器无法构造最低必要条件的部署时：

- 环境记录硬违约并推进窗口；
- 该原始扩散动作仍属于当前策略轨迹，保留其对数概率和负奖励；
- 不伪造投影后动作；
- 快层执行器不执行不存在的部署。

## 12. 奖励与指标

第一版继续使用已批准的简化奖励：

```text
total_cost = run_cost + route_cost + cold_start_cost
reward = -(min(total_cost / maximum_window_cost, 1) + violation_penalty)
```

任何资源、可靠性、路由或 SLA 硬约束失败都令
`violation_penalty = 1`，否则为 0。第一版不新增需要调参的投影惩罚权重。

投影修改率、修复次数和原始可行率只作为训练诊断与实验指标。在后续消融
实验中，只有明确证据表明策略依赖投影器且无法改善时，才单独设计固定
投影成本，并作为新设计再次 review。

## 13. 检查点和输出隔离

DPPO 检查点元数据至少包含：

```text
state_schema_version = dppo-v1-78
action_schema_version = joint-sfc-continuous-v1
state_dim = 78
action_dim = 27
function_count = 3
compute_node_count = 6
diffusion_steps = 20
fine_tuned_steps = 5
maximum_retention_seconds
replica_threshold = 0
configuration_hash
```

数据集、预训练模型、在线模型、训练表格和图像使用 DPPO 独立目录。烟雾
运行必须支持 `--output-root`，不得覆盖 DDQN 基线或正式论文结果。

## 15. 测试策略

实现严格遵循测试先行。测试分为：

1. **动作单元测试**：27 维形状、范围、2/3 阈值、节点排名、TTL 缩放；
2. **投影单元测试**：故障节点、重复节点、故障域、资源不足和确定性平局；
3. **保留时间测试**：到期、刷新、故障、冷启动和内存占用；
4. **数据测试**：固定种子复现、分区无泄漏、模式版本校验；
5. **扩散测试**：前向加噪、反向形状、对数概率和损失均为有限数；
6. **DPPO 测试**：GAE、裁剪概率比、冻结早期去噪步、Rollout 清空；
7. **环境集成测试**：一次联合部署 3 个 VNF、快层调用次数、奖励闭环；
8. **检查点测试**：保存重载一致和旧 DDQN 检查点拒绝；
9. **烟雾测试**：小数据预训练、一 Episode 在线更新和临时目录评估。

原有完整测试必须继续通过；DDQN 基线测试不得通过放宽断言来掩盖接口破坏。

- 成本优先、可靠性优先和平衡规则教师；

## 17. 完成标准

代码实现完成必须同时满足：

1. 状态版本为 `dppo-v1-78`，无未来请求泄漏；
2. DPPO 生成 27 维有限连续动作；
3. 一次动作联合包含全部 3 个 VNF；
4. 每个 VNF 可独立选择 2 或 3 副本；
5. 中心云通过同一节点评分参与选择；

7. 仿真专家数据按 Episode 隔离切分；

10. 原始、投影和最终动作指标可分别导出；
11. DDQN 仍能作为基线加载其匹配版本的模型；
12. 完整测试、语法检查、临时预训练和在线烟雾训练全部通过；
13. 正式结果路径在用户另行批准前不被覆盖。
