# DPPO 预训练有效性双指标诊断设计

## 1. 目标

本诊断用于回答两个彼此独立的问题：

1. 预训练扩散模型生成的连续动作是否比随机初始化模型更接近专家动作；
2. 连续动作误差的变化是否真正转化为节点部署、副本数量、保留时间和原始可行性的改善。

诊断只读取现有 `dppo-expert-v2` 数据集和预训练检查点，不修改奖励函数、预训练目标、在线 PPO、动作投影器或 CLARABEL 快层求解器，也不运行基线算法或独立性能评估。

## 2. 对比对象与数据范围

诊断比较两个结构完全相同的条件扩散模型：

- **随机模型**：使用固定初始化种子创建，不加载任何训练参数；
- **预训练模型**：从指定 `dppo_pretrained.pt` 恢复。

只使用数据集的验证分区和测试分区，训练分区不参与诊断。当前中等规模数据集包含 12 条验证记录和 11 条测试记录，共 23 条未用于参数更新的可行专家记录。

两个模型对同一条状态使用相同的扩散采样种子和相同的采样标准差下限。这样生成差异只来自模型参数，不来自初始噪声或采样设置。

## 3. 诊断流程

### 3.1 兼容性门禁

运行前必须验证：

- 数据集 schema 为 `dppo-expert-v2`；
- 状态、动作 schema 和维度与当前配置一致；
- 预训练检查点的配置哈希、MEC 数、VNF 数、副本上下限和扩散步数与当前配置一致；
- 验证分区和测试分区均非空；
- 所有待诊断记录都满足 `expert_action_feasible=True` 和 `final_feasible=True`。

任一条件不满足时直接失败，不生成容易误解的部分报告。

### 3.2 场景重放

记录按 `episode_seed` 和 `slow_step` 排序并分组。每个 Episode 使用数据中的教师名称重新创建教师策略：

1. 使用 `episode_seed` 重置场景；
2. 按原教师策略逐慢步生成建议并通过原环境执行；
3. 在每个目标慢步执行前取得当前状态和投影输入；
4. 当前状态必须与数据集保存的状态在浮点容差内一致；
5. 若状态不一致，立即报告 seed 和 slow step 并失败。

这种重放方式能够恢复动作产生时真实的运行节点、剩余 CPU、剩余内存和故障域，而不是使用执行后的未来资源状态。

### 3.3 公平动作采样

对每条记录，随机模型和预训练模型分别从完整扩散链生成一个连续动作。采样种子由固定基础种子、Episode seed 和 slow step 确定，并对两个模型完全相同。

采样使用当前配置中的评估标准差下限，输出仍经过现有动作空间的 `[-1, 1]` 范围处理。诊断不对生成动作增加额外修正。

## 4. 指标定义

### 4.1 连续动作拟合指标

每条记录分别计算随机模型和预训练模型相对专家动作的：

- **动作 MSE**：完整连续向量的均方误差；
- **动作 MAE**：完整连续向量的平均绝对误差。

汇总时输出均值、中位数，以及预训练模型逐记录误差低于随机模型的记录比例。

### 4.2 解码语义指标

使用现有动作空间解码模型动作和专家动作，按 VNF 汇总：

- **副本数准确率**：生成副本数与专家副本数相等的 VNF 比例；
- **节点前缀完全命中率**：生成节点排名的前 `专家副本数` 个节点与专家前缀顺序完全一致的 VNF 比例；
- **节点集合命中率**：忽略顺序后，生成前缀与专家前缀节点集合相等的 VNF 比例；
- **主副本保留时间 MAE**；
- **备副本保留时间 MAE**。

前缀指标只检查实际部署所需的节点数量，不要求未部署节点的完整尾部排名完全相同。

### 4.3 原始可行性指标

使用场景重放得到的执行前投影输入，对两个模型的解码动作调用现有投影器，汇总：

- **原始可行率**：`projection.raw_feasible=True` 的记录比例；
- **投影成功率**：`projection.success=True` 的记录比例；
- **平均投影修改比例**；
- **投影失败原因计数**；
- **生成副本数分布**。

诊断不会把投影后的动作当成模型原始输出，也不会把投影修改量加入奖励。

## 5. 结果判读

诊断输出方向性结论，不作为正式论文显著性检验：

- 若预训练动作 MSE 相对随机模型下降至少 10%，且超过一半记录的 MSE 得到改善，则认为预训练学到了连续专家信号；
- 若连续误差改善，同时副本准确率、节点前缀指标或原始可行率至少一项改善，则认为专家信号开始转化为部署语义；
- 若连续误差改善但语义和可行性均未改善，则优先检查连续动作参数化到离散部署的映射；
- 若连续误差未达到上述条件，则优先检查预训练更新次数、batch size、数据规模和噪声预测目标，不进入新的在线大训练；
- 23 条记录只用于工程诊断，不宣称统计显著性或算法优越性。

## 6. 输出产物

新增只读命令行入口，要求显式提供：

- 配置文件；
- 数据集目录；
- 预训练检查点；
- 输出目录；
- 运行设备；
- 可选的固定诊断种子。

输出目录包含：

- `per_record_metrics.csv`：每条记录、每个模型的连续误差、解码语义和投影结果；
- `summary.json`：数据/检查点摘要、聚合指标、相对改善量和方向性结论。

JSON 必须使用有限数值并稳定排序，CSV 和 JSON 都使用 UTF-8。运行产物放在被 Git 忽略的 `results/dppo/` 下，不上传模型或逐记录运行数据。

## 7. 代码边界

计划新增：

- `src/dppo_pretraining_diagnostics.py`：纯指标、聚合和结果数据结构；
- `run_dppo_pretraining_diagnostics.py`：加载、场景重放、模型采样和写出；
- `tests/test_dppo_pretraining_diagnostics.py`：核心行为测试。

必要时只复用现有 `dppo_dataset`、`dppo_checkpoint`、`dppo_diffusion`、`dppo_scenario` 和 `dppo_teacher` 公共接口，不修改它们的算法行为。

## 8. 测试与失败处理

采用测试驱动实现，核心测试只覆盖：

1. 连续误差和解码语义指标计算正确；
2. 相同种子产生可复现的随机/预训练公平采样；
3. 场景状态重放一致，状态不匹配时明确失败；
4. 不兼容 schema、配置哈希或检查点被拒绝；
5. CSV/JSON 字段齐全且只包含有限数值；
6. 命令行必须显式指定数据、检查点和输出目录。

不增加大范围全量测试，不修改训练超参数，也不在本任务内自动启动新的在线训练。
