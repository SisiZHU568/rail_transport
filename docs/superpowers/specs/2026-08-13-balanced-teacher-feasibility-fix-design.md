# BalancedTeacher 可行性修复设计

## 1. 目标

在扩大 DPPO 训练规模前，先修复 `BalancedTeacher` 生成专家标签时可行率过低的问题，确保 balanced 类标签能够稳定进入训练集、验证集和测试集。

本次只调整教师标签生成规则，不修改：

- DPPO 网络、PPO 更新过程和奖励函数；
- 动作投影器及其奖励关系；
- 快时间尺度 CLARABEL 求解器；
- `CostTeacher` 和 `ReliabilityTeacher` 的行为。

## 2. 诊断依据

现有 120 episode 数据中，balanced 候选共 80 个，但只有 2 个通过质量门禁，并且验证集和测试集均没有 balanced 标签。

对同一批场景进行消融后：

- 当前规则“3 副本 + 成本优先”的通过率约为 2.5%；
- 改为“配置中的最低副本数 + 可靠性优先”后，通过率为 100%；
- 独立新种子复核中，新规则仍为 80/80 通过。

因此问题主要来自教师启发式本身，而不是 DPPO、投影器或 CLARABEL。

## 3. 行为修改

修改 `src/dppo_teacher.py` 中的 `BalancedTeacher`：

1. 副本数从“最低副本数再加 1”改为直接使用配置中的 `minimum_replicas`；
2. 节点排序从成本优先改为可靠性优先；
3. 继续使用现有的故障域分散选择，避免副本集中在相同故障域；
4. 主副本与备份副本的保留时长计算保持不变。

这样 balanced 教师仍然同时考虑可靠性、故障域分散和资源保留，但不会因为额外副本及低可靠节点组合而大量生成不可执行标签。

## 4. 数据版本隔离

在 `configs/dppo/debug.yaml` 的数据集配置中增加教师规则版本标识，例如：

```yaml
teacher_schema_version: balanced-min-replica-reliability-v1
```

配置加载时要求它是非空字符串。该字段会自然进入现有配置哈希，从而保证：

- 修改前后的专家数据不会被误认为来自同一配置；
- 旧专家预训练 checkpoint 不会被误用于新教师规则；
- 后续论文实验可以明确追溯所用教师规则版本。

这里不新增可调超参数，只增加规则版本记录。

## 5. 核心测试

只补必要的行为测试：

- balanced 副本数等于配置中的 `minimum_replicas`；
- balanced 按可靠性选择节点，并继续满足故障域分散；
- balanced 的保留时长公式没有改变；
- 教师版本字段缺失、为空或类型错误时明确拒绝；
- 现有教师、数据集和预训练核心测试继续通过。

## 6. 修复后的 120 episode 门禁

代码通过核心测试后，重新生成 120 episode 专家数据到新的输出目录，不能覆盖旧诊断数据。继续扩大规模前必须满足：

- balanced 候选总体通过率不低于 90%；
- cost、reliability、balanced 三类教师在训练集、验证集和测试集中都至少有 1 条有效标签；
- 所有保存标签均通过原始动作可行性、最终动作可行性和快层执行检查；
- 数据生成过程没有未处理异常。

若门禁通过，下一阶段直接扩大专家数据规模并重新进行预训练；若不通过，只针对实际失败原因继续修复，不提前改 DPPO 奖励或模型结构。
